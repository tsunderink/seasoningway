# 地圖頁引擎

把一趟旅程的地點做成一個互動地圖頁（單一 `index.html`，發布成私人 artifact），有「我的行程」「景點清單」「住宿清單」三個分頁。使用者在頁面上排行程、加星號，資料存在 artifact 資料庫和瀏覽器裡。開車時數目前只算自駕；底圖腳本 `basemap_tiles.py` 目前只支援日本。

## 一趟旅程的檔案

| 檔案 | 內容 | 來源 |
|---|---|---|
| `places/<id>.json` | 地點，一筆一個檔，格式見 [place.schema.json](../src/seasoningway/schemas/place.schema.json) | Claude、`spot-scout` 寫 |
| `map/config.json` | 頁面設定：標題、類別、評分網站、季節推薦度、開車參數、底圖範圍，格式見 [map.schema.json](../src/seasoningway/schemas/map.schema.json) | 手寫 |
| 旅程 `README.md` 開頭的 `start`、`end` | 頁面的日期 | 手寫 |
| `map/regions.json` | 一級行政區界（GeoJSON），`properties` 要有 `zh`（名稱）、`focus`（是不是重點地區）；拉遠時在圖磚上面畫界線和名稱 | 從行政區界開放資料轉，出處寫進設定的 `basemap.credits` |
| `cache/base/` | 底圖：`tiles/` 圖磚大圖、`tiles.json` 範圍、`places.json` 地名 | `basemap_tiles.py` |
| `cache/roads.txt`、`cache/roads.json` | 開車路網和每個地點接上的路口（選用；沒有就全用直線估） | `roads.py` |
| `cache/place_ids.json` | Google 地圖的 Place ID（選用），只存 ID，不存 Google 的名稱、座標 | `place_ids.py` |
| `map/photos.json`、`map/photos/` | 照片和授權資訊（選用），`photos.json` 的鍵是地點 id | 手動 |
| `published.json` | 上次發布的 artifact slug、版本與來源和快取的雜湊 | `seasoningway published` |
| `out/<旅程>/map/index.html` | 地圖頁，與路網、圖磚及照片一併產出 | `seasoningway render` |

這些產物與快取的保存規則見 [設計](design.md#4-產物與快取)。旅程自己的說明（artifact 連結、照片進度、底圖已知限制）放在旅程的 `map/README.md`。

## 指令

| 指令 | 輸入與結果 |
|---|---|
| `seasoningway render <旅程>` | 驗證後產生 `out/<旅程>/map/`，有 `map/config.json` 的旅程才產生地圖 |
| `seasoningway fetch <旅程> drive` | 預設讀 `itinerary.json`，或用 `--plan <JSON>` 讀地圖頁行程。透過 OSRM 試算，結果寫進 `cache/drive.txt` |
| `seasoningway fetch <旅程> roads --pbf <檔案>` | 用已擷取旅程範圍的 OSM PBF 建路網。可用 `--date YYYY-MM-DD` 記資料日期。抓路網時另外安裝 `osmium` |
| `seasoningway fetch <旅程> basemap --work <資料夾> --rail <GeoJSON>` | 用 N02 鐵路與地圖設定畫底圖。可用 `--date YYYYMMDD` 指定 Protomaps 建置日期 |
| `seasoningway fetch <旅程> place-ids` | 預設查還沒有 ID 的地點。可加 `--ids <ID …>` 或 `--all`。用環境變數 `GOOG_MAPS_DEMO_KEY` 提供金鑰 |

底圖工具需要在工作目錄安裝 Node 的 `maplibre-gl@5`、`@protomaps/basemaps@5`、Playwright 與無頭 Chromium，另在執行引擎的 Python 環境安裝 `pmtiles shapely mapbox-vector-tile requests pillow numpy`。中文與日文字型使用 Noto Sans CJK。詳見 [底圖程式](../src/seasoningway/tripmap/basemap_tiles.py)。

[地圖測試](../tests/test_tripmap.py) 用虛構資料 render。瀏覽器測試用 Node 的 Playwright 和 Leaflet 1.9.4，在桌面與手機尺寸操作三個分頁並檢查 JS 錯誤。

## 發布

1. 第一次：發布 `out/<旅程>/map/` 的頁面和相鄰資源，再執行 `seasoningway published <旅程> <版本號> --slug <slug>`。
2. 更新：`check` 會指出變動的來源和快取。重新 render 和發布，移除已從產物刪掉的檔案，再執行 `seasoningway published <旅程> <新版本號>`。

artifact 的一個版本最多 512 個檔，頁面、照片、底圖大圖加起來要在這之內，所以圖磚每 4×4 張拼成一張大圖。

## 讀使用者在頁面上的資料

用 db_get 讀 artifact 資料庫；使用者也可以直接貼「複製星號清單」或「複製行程文字」的內容。瀏覽器裡另外存了一份（localStorage `<storage_prefix>-stars`、`<storage_prefix>-plan`）。

- `plan/stars`：`ids` 是加了星號的地點 id，`updated` 是更新時間。
- `plan/itinerary`：`days` 以日期為鍵，每天的 `ids` 是照順序排的地點 id，`stay` 是住宿 id。
- 把 `plan/itinerary` 存成檔案後跑 `fetch <旅程> drive --plan <JSON>`，可以得到逐天的開車里程、時數、高速里程和預計到住處的時間。下面三種情況會標 ⚠️：超過每天的開車上限、晚於設定的 `arrive_by` 才到、撞到公休日。

## 改地點

- 一個地點就是一個檔：`places/<id>.json`。改完後，用 `seasoningway check` 驗證 schema。
- 不能改 `id`，也不能改檔名：使用者的行程、星號、`photos.json`、`place_ids.json` 都是用 id 記的。刪地點前，先確認行程和星號裡沒有用到它。
- `as_of` 是整筆資料的查詢日期：整筆的來源都重新對過才改；只改推薦度這類 Claude 自己的評估時不改。`visit.as_of` 是停留時間的查詢日期，另外記。
- 新增：照 schema 寫一個新檔，檔名就是 `id`。蒐集的經過（使用者要求、候選從哪裡來、挑選標準、排除了什麼、未確認的事）寫進旅程的 `research/scouting.md`。
- 欄位用法（完整定義在 schema 的 `description`）：
  - `categories`：第一個是主要類別，都要定義在設定的 `categories`。
  - `season.tier`：旅行月份的推薦度 1–5，每一級的意思寫在設定的 `season.tiers`。住宿和租車點不填。
  - `facts`：標籤寫成「項目（來源）」。公休的標籤用「休息」開頭，星期寫「週二」或原文（例如「火曜定休」），日期寫 YYYY-MM-DD，這樣 `plan_drive.py` 才比對得到。
  - `contact`：地址、電話。
  - `website`：地點自己經營的官網；比價、訂房、旅遊情報網站不算。
  - `visit`：預計停留時間。排進行程的點才加，單位是分鐘，含排隊、買票、從停車場走過去，不含開車。找不到公開的建議時間，`note` 開頭寫「沒有找到公開的建議時間」；是使用者自己定的，就寫「使用者定的時間」和日期。
  - `map_query`：地圖 App 的搜尋文字，預設是「原文名稱＋地區」。名稱太長或含兩個地名時自己指定；遇到泛指一類的店、列車這種搜不到特定地點的，填 `false`，改用座標。
  - `lodging`：住宿，填 `area`（溫泉鄉或城市）。使用者說了名字才加，Claude 不自己挑旅館。
  - `rental`：租車的取車點填 `pickup`，還車點填 `dropoff`。

## 介面規格

這些是定下來的行為，括號裡是原因。改 `template.html` 前先讀相關的那一項，別改回去；改了介面就同步更新這裡。通用化的待辦見 [roadmap.md](roadmap.md)。下面說的「地區」是地點的 `region`，在頁面上的叫法照設定的 `texts.region_word`，例如「縣」。

### 整體

- 頁首說明、頁尾文字和統計卡同寬，不限行長（只佔左半邊看起來像被切掉）。
- 版面：桌面左邊是滿版地圖、右邊是清單；手機地圖固定在上、清單在下，延伸到螢幕左右兩邊。
- 顏色只有兩種意思：藍＝介面和使用者的選擇（路線、選中、目前這天、星號）；紅、橘、黃、灰＝推薦度；住宿用中性深灰（地圖參考 Google 地圖）。
- 介面列用同一種半透明毛玻璃、高 44px；尊重系統的「降低透明度」和「減少動態效果」（照蘋果的設計原則）。
- 地圖控制項：
  - 放在右上（全程／這天、放大縮小）；不自動縮放，只有按按鈕才縮放。
  - 點了某一天，那天的路線變粗，其他天淡到 55%，仍看得到全程（淡到 30% 會看不見）；按「全程」時所有天一樣顯示。
  - 圖例在左下（地圖夠大才展開）。
  - 出處收成「© OpenStreetMap」按鈕，點開才看到完整出處（OSM 要求出處看得到）。
- 用語一致：日期寫「1/15（四）」；地圖名稱和當天標題一致；類別名稱在篩選和卡片上一字不差。
- 底圖：
  - 預先畫好的圖磚，來自 OpenStreetMap 資料（Protomaps），有高速公路、國道、主要地方道、鐵路、河川湖泊和山影（只有地形和高速公路不夠用，但不需要太精細）。
  - 分外圍、細緻兩層；放大超過細緻層的最大縮放，就拿最大那層放大顯示。
  - 頁面不能讀外部圖片，所以接不了線上底圖。
- 地名不畫在圖磚裡，由頁面用固定字級另外畫（`base/places.json`；畫在圖磚裡的話，縮放時地名會一瞬間變很大）：
  - 顯示哪些地名看畫面涵蓋的範圍：經度寬或緯度高 × 1.25，取大的那個，各裝置一樣。
    - 13 度以上什麼都不寫；大到半個國家只寫地區名。
    - 6.5 度以下加首府，4.5 度以下加 20 萬人以上的市，3 度以下加 10 萬人以上的市。
    - 3.3 度以下地區名收起來；2.2 度以下加其他的市；0.8 度以下加町（`PREF_SPAN`、`PLACE_SPAN`；拉遠時要少一點）。
  - 被景點或景點名稱擋到、或和更重要的地名重疊就藏起來，四周多留 6px。壓到還沒排的小圓點時，先往上或往下挪一點，挪不開就不寫，首府也一樣（參考 Google 地圖 app）。超出地圖邊緣的不放，只放畫面附近的。
  - 地名是底圖的一部分，畫在路線、圖釘、小圓點下面；用灰色細字（首府 12px 並拉開字距、大城市 12px、其他 11px），和景點名稱的深色粗字分得出來（不搶焦點）。
- 地區界線、地區名另外畫在圖磚上面（`regions.json`）；可以縮小到看見全程，往外移動也有餘裕；地區名不重疊，被景點擋到就藏。

### 我的行程

- 旅程的每一天：景點照順序排，加上「今晚住哪」（最後一天沒有）。同一個點只排一天，住宿可以連住。設定的 `preset` 可以預先放點（例如已訂門票的景點），使用者可以移走。
- 預計停留時間：
  - 行程的每一列，摘要開頭標「停留 1–1.5 小時」（景點清單不標）。
  - 每天標題下加總「停留約 3.5–6 小時」，取到半小時，沒估的寫有幾個沒估。
  - 展開的卡片，事實表第一列寫依據，標明是 Claude 估計。
  - 「複製行程文字」也帶上停留時間。
  - 趕不趕得上入住由 Claude 檢查行程時判斷，頁面不判斷。
- 「在 Google 地圖看這天路線」：
  - 有開車的日子，在大標題日期那一行的右邊放「Google 地圖 ↗」。起點是前一晚的住處（還沒定就用前一天最後一個點），中途依序是景點，終點是今晚的住處。連結跟著行程即時產生，不用重新發布；只連出去、不嵌入。
  - 每個點用 `gq`（`map_query`）搜尋，Google 才會顯示景點名而不是地址；沒有 `gq` 的用座標。有 Place ID 就一起帶，Google 以 Place ID 為準；中途點每個都有 Place ID 才帶 `waypoint_place_ids`。
  - 中途點超過 3 個時，手機要用 App 開（手機瀏覽器只帶得了 3 個）；超過 9 個只帶前 9 個。這些限制寫在頁首說明和連結的滑鼠提示裡（[Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started)，查詢於 2026-11-23）。
  - Place ID 用 `place_ids.py` 查，只查排進行程的點（demo key 有額度限制）。查完要 render，然後重新發布。
- 開車路線和時數（草案，MVP）：
  - 頁面載入 `roads.txt` 後，每一段都在瀏覽器裡用 A* 算最快路線，沿路畫線。時速用設定的 `drive.network`，不含塞車、天候。改了行程就馬上重算。
  - 路網還沒載入、或某個點接不上路網時，那一段用直線估（設定的 `drive.straight`），標題下寫「直線估算」或「部分直線估算」。超過 `drive.max_hours` 標 ⚠️。路線上標順序編號。
  - 只算取車點到還車點之間：取車那天從取車點算起，還車那天算到還車點為止，其他沒租車的日子在標題下寫「沒租車」。只看取還車點排在哪天，不看租車日期：取車點沒排就從第一天開頭算，還車點沒排就算到最後一天。取車前、還車後的移動（電車、計程車）不算。
  - 路網收全區的高速、國道、主要地方道和縣道；市町村道以下，只留每個景點接到主要道路的那一段。旅行期間封閉的路不收：OSM 有標的（`*:conditional`）加上設定的 `drive.closed_roads`。
  - 新增景點後要重跑 `roads.py`，沒有接上路網的那一段用直線估。只加一兩個點時，可以直接在 `roads.json` 的 `snap` 填最近的路口編號；要選不是只接高速、也不是單行道的路口。
- 取還車點：放在景點清單的「租車取還」類別（`car`），和景點一樣排。
- 排法：
  - 從景點清單用 ⠿ 拖到底部的日期列（住宿類會設成那晚的住宿），或按 ＋ 選日期、「住這晚」。
  - 已排的點，＋ 換成實心藍 ✓；選單裡每天列出排了的景點名稱和住宿。
  - 在行程裡，⠿ 可以調順序、換天、拖到「今晚住哪」；⋯ 選單可以上移、下移、移除；每次改動都可以「復原」。
  - 在景點清單的地圖上，點還沒排的點也會跳出選單。
  - 「我的行程」分頁不顯示篩選列，地圖上也不畫還沒排的點，只看行程。
- 拖曳用 pointer events 自己做，只有把手設 `touch-action: none`（不這樣做有時候抓不起來）：
  - 把手看起來是 28×40，可以按的範圍撐滿整列的高度、寬約 36px。
  - 「已調整…／復原」提示上只有按鈕會擋觸控。
  - 上一次拖曳沒收到放開時，下一次按下會先清掉。

### 分頁之間

- 我的行程和景點清單可以互相跳到同一個點（⋯／✓ 選單、展開的小卡）：
  - 那一列閃一下外框。
  - 被篩選藏起來就清除篩選；所在的地區收合了就先展開。
  - 只住不玩的點，跳到第一晚的「今晚住哪」。
- 切換分頁時，各自回到上次看的位置，展開的卡片照舊；第一次切過去從清單開頭（篩選列下面）開始，不是整頁最上面。記的是閱讀線上的那一列，不是捲動像素；重新整理後從開頭開始。

### 選中（只靠點選）

- 只有點選才換選中的點：點清單的列（展開小卡）或地圖上的點。三個分頁捲動時都不選，地圖也不動（捲動時自動選中清單最上面那張的話，地圖會一直跳，iPad 捲動也會卡）。選中的點保留到點下一個為止，換分頁、按篩選都不變。
- 樣式含蓄：清單那一列加淡底色和左側細色條，不用粗框、三角形，照片不蓋住色條；地圖上的點放大、加光圈、一定顯示名稱。
- 點清單的列：點在地圖中間範圍外（四邊各留 22%）時，才移到正中間（只移到貼邊不好看）；靠近底圖邊緣時只移到允許的最遠處，不先移過頭再拉回。點地圖上的點：清單捲到那一列並展開。
- 我的行程的「目前這天」（路線加粗、大標題加底色）也只有點選才換：點那天的景點、大標題、精簡列或路線。「這天」按鈕放大目前這天；還沒點過就用正在看的那一天（閱讀線是精簡列下緣往下 64px）。另外兩個分頁不強調哪一天，「這天」不能按。
- 清單的列上不掛一般的 pointer、touch 監聽，只有拖曳把手掛 passive 的 pointerdown（掛了會滑不動）。

### 「第 X 天」精簡列

- 大標題捲上去後，固定在清單頂端，漸變跟著捲動位置走，下一天會把它推走；點它回到那一天的開頭；下面沒內容的天不顯示。
- 層次：天數 → 標題 → 日期（靠右、短格式）；底邊有「這天看到哪裡」的進度條；換天時，路線粗細和大標題底色淡入淡出。

### 篩選

- 頂端列只有一行檢視分段控制，三個分頁一樣高，切換時地圖不跳（篩選放在頂端列第二行的話，在我的行程藏起來時會抖）。
- 篩選只放在景點清單：在清單欄最上面，捲動時黏在頂端列（手機是黏在地圖）下面。只有一行，放不下就左右滑，不用彈出面板。
- 套用到景點清單和地圖上還沒排的點；住宿清單不套用。按篩選時，正在看的卡片原地不動。
- 篩選列：推薦度下拉（必去／推薦／有空再去）；類別按鈕上的數字是符合推薦度條件的數量（0 變灰），選中的是淡藍底；可以只看「已加星號」。

### 地圖上的點（參考 Google 地圖）

- 行程裡的點先完整顯示，擠在一起才縮成小點；同類的主要景點重疊時合成「16·17」，放大後恢復。點不做半透明，縮小只代表擁擠。
- 還沒排的點，在縮放 9（`NEAR_SYM_Z`）以下只是小點，以上才畫類別符號，選中的例外（拉遠時符號太雜）。
- 放到最大（11.5 以上，`SPREAD_DZ`）還擠在一起的點，挪到旁邊，用細線和小圓點連回實際位置（`spreadSpot`）。細線畫在所有圖釘下面的獨立一層，彼此不交叉、不穿過別的圖釘，名稱不蓋住細線。
- 名稱用描邊字，放得下才顯示，互不重疊。

### 卡片

- 展開的小卡不重複摘要；內容展開時才產生；照片矮一半。
- 營業時間、費用整理成一致的格式，保留評分網站上的原文。
- 推薦度框寫出每一級的意思，標明是 Claude 評估。評分框一個網站一框，照設定的 `ratings` 排，標題括號寫這個分數代表誰的意見（`about`）。
- 資料來源：官網排第一，再來是評分網站，最後是其他來源，網址相同的只列一次。
- 「在地圖 App 看」：Google 地圖、Apple 地圖的連結，只連出去、不嵌入。
  - Google 地圖有 Place ID 就指定那個地點；沒有就用 `gq` 搜尋；連 `gq` 都沒有才用座標（只有座標看不出是哪裡）。
  - Apple 地圖在座標放圖釘並標上名稱。
  - `location.approximate` 的點標「大概位置」（Google 用名稱搜尋時，只有 Apple 地圖是大概位置）。

### 星號

- ☆ 是使用者「想去」的記號，卡片、小卡、景點清單上都有；地圖上加了星號的點，右上角有藍色小星。星號同步到 artifact 資料庫，另外有「複製星號清單」。

### 景點清單

- 全部景點依地區分組，篩選照樣能用，每一列標出排在第幾天或住哪一晚。
- 點地區名可以收合，另外有「全部地區收合／展開」（存在 localStorage `<storage_prefix>-folded`）。地區名旁標出星號數和已排幾個；在地圖上點到收合地區裡的點，會自動展開。

### 住宿清單

- 依地區分組，先列旅館，再列「住宿地區」（還沒選旅館時，用城市或溫泉鄉佔位，也可以當景點排）。
- 旅館只能設成住宿（最後一天不能住）；拖到別的地方就提示原因，不改行程。
- 不套用景點篩選，篩選列換成同樣高度的一行說明；地圖只顯示住宿的點。
